# История изменений

## Не выпущено

- SSH fingerprint сохраняется сразу после подтверждения пользователем, а не только при успешной установке ключа Ven4Control: раньше Windows-устройства (автоматическая установка ключа поддерживает только Linux и OpenWrt) и устройства, добавленные с готовым SSH-ключом или без установки ключа, оставались без отпечатка навсегда — они были видны в списке, но ни управление, ни терминал, ни файлы, ни RDP не работали. Установка ключа стала отдельным необязательным шагом: её неудача больше не отменяет управление устройством по паролю.
- Поле «Пользователь» при добавлении устройства больше не заполнено значением `root`: это подсказка, а не значение — незамеченный `root` давал `Permission denied` на Ubuntu-сервере и Windows-ПК.
- Импорт из Tailscale спрашивает имя пользователя SSH (один раз на весь импорт) вместо жёсткого `root` и сам получает SSH fingerprint найденных устройств: раньше импортированные устройства были заведомо неуправляемыми. Не ответившие устройства добавляются как раньше, без отпечатка; итог импорта прямо называет применённого пользователя.
- Операции, у которых есть только POSIX-реализация (обзор, сервисы, логи, перезапуск сервиса, перезагрузка, обновление пакетов, резервная копия конфигов), отвечают на Windows-устройствах понятным отказом вместо ошибки PowerShell «не является внутренней или внешней командой».
- Исправлено фоновое логирование Windows-устройства: команда журнала завершалась сразу, что распознавалось как обрыв связи, и сессия бесконечно переподключалась, дописывая маркеры «ОТКЛЮЧЕНО» в файл журнала. Теперь такая сессия останавливается с понятным сообщением.
- Архив Ven4Tools проверяется по контрольной сумме sha256 из ответа GitHub API до распаковки на устройстве, а сама установка требует подтверждения с описанием того, что и откуда будет установлено.
- SSH fingerprint устройства сверяется во время обмена ключами, до отправки пароля или приватного ключа: раньше соединение открывалось сразу с паролем, а отпечаток проверялся уже после успешного входа — в недоверенной сети пароль успевал уйти тому, кто ответил на соединение. Отпечаток для подтверждения теперь читается вообще без учётных данных, а тип устройства определяется после подтверждения.
- `powershell.exe` и `icacls` запускаются по абсолютному пути из `%SystemRoot%\System32`: имя без пути Windows ищет в том числе в рабочем каталоге процесса, и подложенный рядом с приложением файл выполнился бы с уже подтверждёнными правами администратора.
- Учётная запись передаётся `icacls` и планировщику задач в виде SID: составное имя `КОМПЬЮТЕР\пользователь` не сопоставляется с доменной учётной записью, из-за чего на машине в домене приложение падало при каждом запуске.
- Ошибка подготовки ключа приложения больше не роняет запуск: показывается понятное сообщение, а недозащищённый ключ не остаётся на диске.

## 0.4.1-beta — 2026-09-09

- Добавлен стартовый каталог на странице «Приложения» для OpenWrt/Linux-устройств: при первом заходе на страницу таблица сама заполняется первыми 200 пакетами из репозитория, без ввода поискового термина — можно сразу просматривать и выбирать, а поиск сужает список при необходимости.

## 0.4.0-beta — 2026-09-09

- Добавлена страница «Приложения» в диалоге управления устройством: поиск и установка пакетов из уже настроенных на устройстве репозиториев — `apk`/`opkg` для OpenWrt, `apt` для Ubuntu/Debian, `winget` для Windows.
- Добавлена кнопка «Установить/обновить Ven4Tools»: скачивает последний релиз с GitHub и распаковывает в `C:\Ven4Tools` — пригодится, когда на устройстве изначально нет нужной службы (например, SFTP).
- Добавлено восстановление после обрыва SSH-соединения при установке Ven4Tools: если канал рвётся уже после того, как установка на устройстве реально завершилась (случается при долгой передаче по нестабильной сети), приложение переспрашивает устройство отдельным соединением вместо того, чтобы сообщать о мнимой ошибке.

## 0.3.0-beta — 2026-09-08

- Добавлена система тем интерфейса (4 темы, как в Ven4Tools) и диалог «Настройки».
- Добавлена независимая тема встроенного терминала: по умолчанию следует за темой приложения («Как в приложении»), но можно закрепить свою — дальнейшая смена темы интерфейса терминал больше не трогает.
- Главное окно переведено на сайдбар в стиле Ven4Tools: логотип, разделы «Устройства»/«Выбранное устройство»/«Массовые операции», статус-пилюля «Онлайн: N из M», кнопка «Настройки» — вместо тулбара и отдельной панели действий.
- Разделы сайдбара стали раскрывающимися: «Массовые операции» свёрнут по умолчанию и сам разворачивается, когда отмечено хоть одно устройство.
- Вкладки диалога управления устройством заменены вертикальной навигацией слева, тем же стилем, что и остальной интерфейс.

## 0.2.0-beta — 2026-09-08

- Добавлена группа устройства — свободная метка вида «Дом» или «Работа»: задаётся при добавлении, меняется кнопкой «Изменить группу» и видна отдельным столбцом в списке.
- Добавлены массовые операции по флажкам в списке: перезагрузка и обновление пакетов сразу на нескольких устройствах — с одним подтверждением, независимым выполнением и общим отчётом по каждому устройству.
- Изменена модель подключения по RDP: было прямое подключение к порту 3389 устройства, стало подключение внутри SSH-туннеля — порт наружу не открывается никогда.
- Добавлено определение Windows в опросе платформы: устройства с OpenSSH Server отвечают PowerShell, где POSIX-команды не выполняются.
- Добавлены проверка и включение RDP по SSH через `fDenyTSConnections`; правила файрвола приложение не меняет.
- Добавлена кнопка «Включить RDP» для Windows-устройств с запрещёнными входящими подключениями.
- Добавлен реестр RDP-сессий: туннель и SSH-соединение закрываются вместе с окном `mstsc`, вторая сессия на устройство не открывается.
- Добавлен столбец «RDP» в списке устройств: видно, для какого устройства туннель уже открыт.
- Убраны RDP из панели действий для роутеров и Linux-серверов: там удалённый рабочий стол неприменим.
- Добавлено сохранение результата проверки RDP: при следующем запуске проверять заново не нужно.
- Добавлена опция «Работать в фоне до входа в систему»: задача в планировщике Windows поднимает приложение при загрузке компьютера, даже если в систему никто не вошёл.
- Добавлена защита от второго экземпляра: повторный запуск показывает окно уже работающего приложения вместо второго набора SSH-сессий к тем же устройствам.
- Добавлена температура устройства в показатели системы: самая горячая термозона выводится на вкладке «Обзор» и попадает в снапшоты журнала сессии.
- Добавлен встроенный терминал с PTY: интерактивная оболочка устройства открывается внутри приложения, без запуска внешнего `ssh.exe`; изменение размера окна передаётся устройству, а закрытие окна закрывает SSH-сессию.
- Добавлена вкладка «Файлы»: просмотр папок устройства по SFTP с навигацией, скачивание файла на локальный диск и загрузка локального файла на устройство — по одному долгоживущему соединению, с процентом выполнения передачи.
- Исправлено сообщение об ошибке SFTP: если SSH-сервер устройства не поддерживает подсистему SFTP (частый случай на OpenWrt с dropbear без пакета `openssh-sftp-server`), приложение больше не пишет вводящее в заблуждение «соединение потеряно», а называет настоящую причину.
