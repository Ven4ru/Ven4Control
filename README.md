# 🛰️ Ven4Control

**Ven4Control** — настольное приложение для Windows, которое объединяет в одном окне управление личными OpenWrt-роутерами, Ubuntu-серверами и Windows-машинами: **контролируй, логируй и управляй** 🎛️

Один список устройств вместо блокнота с IP-адресами, портами и ключами. Один клик — и вы видите, что происходит с устройством, читаете его журнал в реальном времени, ставите на него приложение или подключаетесь по RDP.

> ⚠️ Статус: **0.4.1-beta**. Инструмент рабочий и используется автором каждый день, но API и формат хранения ещё могут меняться между версиями.

## ✨ Возможности

### 📋 Устройства в одном месте
- единый список: название, группа, адрес, SSH-порт, пользователь;
- произвольная группа устройства («Дом», «Работа», «Друзья») — своя метка в списке, задаётся при добавлении и меняется в любой момент кнопкой «Изменить группу»;
- статус «в сети / не в сети» и время отклика TCP;
- массовые операции по флажкам: перезагрузка и обновление пакетов сразу на нескольких устройствах — с общим подтверждением, независимым выполнением на каждом и отдельным отчётом по каждому устройству;
- импорт устройств из `tailscale status --json` одним подтверждением.

### 🔐 Безопасное подключение
- вход по паролю (разово) или по готовому SSH-ключу;
- при первом подключении по паролю показывается SSH fingerprint сервера — подтверждаете вы, не приложение;
- собственная пара Ed25519-ключей приложения (генерируется один раз, приватный ключ защищён Windows ACL);
- перед установкой ключа делается backup `authorized_keys`;
- пароли по умолчанию нигде не сохраняются, а если включить — только в Windows Credential Manager, не в базе и не в Git.

### 🎨 Тема интерфейса
- 4 темы: «Как на сайте», «Бирюзовая», «Тёмная», «Светлая» — переключаются в диалоге «Настройки» без перезапуска;
- тема встроенного терминала независима от темы приложения: по умолчанию следует за ней («Как в приложении»), но можно закрепить свою — дальнейшая смена темы интерфейса терминал больше не трогает;
- главное окно и диалог управления устройством — сайдбар-навигация вместо панели инструментов и вкладок: логотип, раскрывающиеся разделы («Массовые операции» свёрнут по умолчанию и сам разворачивается, когда отмечено хоть одно устройство), статус-пилюля «Онлайн: N из M».

### 🖥️ Управление устройством
- CPU, память, диск, время работы, температура самой горячей термозоны, статус Tailscale/WireGuard;
- список и перезапуск сервисов (`procd` на OpenWrt, `systemd` на Linux);
- обновление пакетов, проверка и установка обновлений прошивки OpenWrt (`owut`/`auc`);
- резервная копия конфигурации на локальный диск;
- перезагрузка устройства — с подтверждением.

### 📦 Приложения
- поиск и установка пакетов прямо из уже настроенных на устройстве репозиториев — без своего курируемого каталога: `apk`/`opkg` для OpenWrt, `apt` для Ubuntu/Debian, `winget` для Windows;
- на OpenWrt/Linux страница открывается сразу со стартовым каталогом — первые 200 пакетов репозитория без ввода термина, можно сразу листать и выбирать; поиск сужает список при необходимости;
- кнопка «Установить/обновить Ven4Tools» — скачивает последний релиз с GitHub и распаковывает в `C:\Ven4Tools` на Windows-устройстве, тот же путь и для первой установки, и для обновления;
- если долгая загрузка обрывает SSH-канал уже после того, как установка на устройстве реально завершилась, приложение переспрашивает устройство отдельным соединением вместо ложного сообщения об ошибке.

### 📡 Фоновое логирование
- держит открытый канал `logread -f` / `journalctl -f`, а не разовый снимок последних строк;
- переподключается с нарастающей задержкой (2 → 5 → 10 → 20 → 30 сек), поэтому перезагрузка устройства обрывает канал, а не сессию наблюдения;
- раз в полминуты дописывает в журнал снапшот показателей системы — удобно искать корреляцию между сбоем и нагрузкой;
- сессия живёт на уровне приложения, а не окна: свернули в трей, закрыли диалог управления — логирование продолжается;
- при остановке журнал сохраняется в TXT, DOCX или XLSX — что удобнее приложить к отчёту;
- сессии, отмеченные для фонового логирования, поднимаются автоматически при следующем запуске;
- опция «Работать в фоне до входа в систему» (в трее) поднимает приложение задачей планировщика Windows ещё до входа пользователя в систему — ночная перезагрузка не прерывает фоновое логирование.

### 🖥️ Подключение по RDP внутри SSH-туннеля
- **порт 3389 наружу не открывается никогда**: RDP идёт целиком внутри уже доверенного SSH-канала — тот же ключ приложения, та же обязательная сверка fingerprint;
- кнопка «Проверить RDP» спрашивает состояние по SSH (`fDenyTSConnections` в реестре), а не стучится в порт устройства;
- Windows с выключенным RDP предлагает кнопку «Включить RDP» — с подтверждением и без единого правила файрвола;
- кнопка «🖥️ RDP» поднимает проброс с локального порта на `127.0.0.1:3389` устройства и запускает `mstsc` на локальный конец;
- закрыли окно RDP — туннель и SSH-соединение закрываются сами; открытая сессия видна в столбце «RDP» и в подсказке трея;
- у роутеров и Linux-серверов RDP не показывается вовсе: он там неприменим, а не выключен.

### ⌨️ Встроенный терминал
- интерактивная оболочка устройства открывается прямо в приложении: тот же ключ, та же обязательная сверка fingerprint, никакого внешнего `ssh.exe`;
- работают стрелки, Tab, Ctrl+C, Ctrl+D и функциональные клавиши, а Ctrl+V вставляет из буфера обмена;
- изменение размера окна уходит на устройство как SSH window-change, поэтому `htop` и `nano` рисуются по фактической ширине;
- разбирается подмножество ANSI/VT100: цвета, начертание, очистка экрана и перемещение курсора — полной эмуляции xterm нет и не планировалось;
- закрыли окно — SSH-сессия закрывается вместе с ним, обрыв связи показывается сообщением, а не молчанием.

### 📁 Файлы устройства по SFTP
- вкладка «Файлы» показывает содержимое папки устройства: имя, тип, размер и права;
- навигация двойным щелчком по папке и кнопкой «Наверх», начиная с домашней папки пользователя;
- скачивание выбранного файла на локальный диск и загрузка локального файла в текущую папку — с процентом выполнения в строке состояния;
- соединение открывается один раз при первом заходе на вкладку и живёт до закрытия окна: клик по папке не платит за новый SSH-handshake;
- нет прав, файл исчез между листингом и скачиванием, оборвалась связь, на устройстве нет SFTP-подсистемы (частый случай на OpenWrt с dropbear без `openssh-sftp-server`) — приложение называет настоящую причину, а не пишет обобщённое «связь потеряна»;
- передаются одиночные файлы: рекурсивной выгрузки папок и пакетного выбора намеренно нет.

### 🧰 По мелочи
- внешний терминал одним кликом (Windows Terminal, с фолбэком на PowerShell);
- автозапуск при входе в Windows через `HKCU\...\Run` — без прав администратора, сразу в трей;
- повторный запуск не поднимает второй процесс: он показывает окно уже работающего, а SSH-сессии остаются в одном экземпляре;
- иконка в трее вместо закрытия по крестику.

## 🚀 Быстрый старт

### Готовый exe

Скачайте `Ven4Control.exe` со страницы [Releases](https://github.com/Ven4ru/Ven4Control/releases) — Python устанавливать не нужно, всё уже внутри.

### Из исходников

```powershell
git clone https://github.com/Ven4ru/Ven4Control.git
cd Ven4Control
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .
ven4control
```

### Требования

- Windows 10/11
- Python 3.12+ (если запускаете из исходников)
- Windows OpenSSH Client
- Windows Terminal — по желанию, для удобного открытия сессии
- Tailscale CLI — только если хотите импортировать устройства из tailnet
- `winget` — для установки приложений на Windows-устройства; уже встроен в Windows 10/11, ставить отдельно не нужно

## 🗂️ Где что хранится

Ven4Control — **приложение одного пользователя**, все данные лежат локально:

| Что | Где |
|---|---|
| Список устройств (без секретов) | `%LOCALAPPDATA%\Ven4Control\devices.db` |
| Пароли/passphrase (если сохранение включено) | Windows Credential Manager |
| Собственный SSH-ключ приложения | `%LOCALAPPDATA%\Ven4Control\ssh\id_ed25519` |
| Журналы фоновых сессий | `%LOCALAPPDATA%\Ven4Control\logs\<устройство>\<дата-время>` |

Ничего из этого не попадает в Git и не покидает компьютер — обновление/переустановка приложения из исходников эти данные не трогает.

## 🛡️ Безопасность

- SSH fingerprint проверяется перед установкой ключа и повторно — непосредственно перед изменением `authorized_keys`;
- существующие ключи на устройстве никогда не перезаписываются, только дополняются;
- приватный ключ приложения защищён Windows ACL (наследование отключено, чтение — только текущему пользователю);
- RDP не требует открытого наружу порта 3389: трафик идёт внутри SSH-соединения с той же сверкой fingerprint, а приложение не добавляет правил файрвола;
- поисковый термин и имя пакета на странице «Приложения» экранируются перед подстановкой в команду устройства (POSIX-приёмом для `apk`/`opkg`/`apt`, PowerShell-приёмом для `winget`) — защита от command injection через поле поиска;
- импорт из Tailscale читает только адреса и имена — не токены и не ключи.

Нашли уязвимость или странное поведение — заведите issue.

## 🧭 Архитектура

```text
Ven4Control
├── PySide6 UI (трей, сайдбар-навигация, диалоги)
├── Theme — палитра приложения (4 темы) + независимая тема терминала
├── DeviceStorage — SQLite без секретов
├── CredentialStore — Windows Credential Manager
├── SSH Service — AsyncSSH, Ed25519, fingerprint pinning, backup authorized_keys
├── Device Control — метрики, температура, сервисы, обновления, бэкап, перезагрузка
├── Remote Control / App Catalog — поиск и установка пакетов (apk/opkg/apt/winget), Ven4Tools
├── Background logging
│   ├── LogSessionManager — реестр сессий на уровне приложения
│   ├── LogStreamWorker — реконнект + периодический снапшот
│   └── RawLogWriter — ротация + экспорт TXT/DOCX/XLSX
├── Scheduled Task — фоновый подъём приложения до входа пользователя
├── RdpTunnelManager — проброс RDP внутри SSH, mstsc на 127.0.0.1
├── Встроенный терминал
│   ├── TerminalSession — интерактивный PTY-канал asyncssh
│   └── TerminalScreen — разбор ANSI/VT100 и отрисовка
├── SftpSession — долгоживущий SFTP-клиент: листинг, скачивание, загрузка
└── Tailscale import — tailscale status --json
```

## 🧩 Ограничения этой версии

- встроенный терминал разбирает только часть ANSI/VT100: альтернативного экрана и мыши нет;
- по SFTP передаются одиночные файлы: папок целиком, пакетного выбора и переименования на устройстве нет;
- страница «Приложения» ставит только из репозиториев, уже настроенных на самом устройстве — установка по прямой ссылке на произвольный скрипт или архив не реализована;
- нет истории показателей за прошлые периоды — только последний снапшот на экране и то, что попало в текстовый журнал фонового логирования;
- рассчитано на одного локального пользователя, не на команду.

## 🔮 Возможное развитие

- установка по ссылке — скрипт-установщик целиком (как у некоторых VPN-клиентов) или архив под конкретную архитектуру устройства, с обязательным подтверждением перед выполнением;
- история показателей (не только последний снапшот).
