# Ven4Control

Ven4Control — закрытое настольное приложение для централизованного контроля личных OpenWrt-роутеров и Ubuntu-серверов через SSH и Tailscale.

Текущая версия: **1.0.0**.

Проект решает практическую задачу: хранить список устройств в одном месте, быстро видеть доступность SSH и открывать терминал без ручного поиска IP-адресов, портов, логинов и ключей.

## Текущий фокус

Версия 1.0 ориентирована на:

- роутеры с OpenWrt и Dropbear;
- серверы с Ubuntu и OpenSSH;
- устройства, доступные по обычному IP, доменному имени или Tailscale IP;
- одного владельца и локальное использование на Windows.

Windows-компьютеры пока не являются основной целью. Для их автоматической подготовки рассматривается отдельный одноразовый конфигуратор `Ven4Node`, но он не входит в версию 1.0.

## Возможности версии 1.0

### Управление устройствами

- единый список устройств;
- название, адрес, SSH-порт и имя пользователя;
- состояния «В сети» и «Не в сети»;
- измерение времени установления TCP-соединения;
- ручное обновление состояния;
- удаление устройства;
- отдельное удаление сохранённых данных подключения.

### Добавление устройства

Поддерживаются два сценария:

1. IP-адрес, логин и пароль.
2. Готовый приватный SSH-ключ.

При добавлении по паролю приложение может:

- подключиться к устройству;
- определить Linux или OpenWrt;
- показать SSH fingerprint сервера;
- запросить подтверждение fingerprint;
- создать резервную копию `authorized_keys`;
- установить публичный ключ Ven4Control;
- переключить устройство на вход по ключу.

Пароль после установки ключа можно удалить кнопкой «Удалить сохранённые данные».

### Tailscale

Кнопка «Импорт Tailscale» выполняет:

```text
tailscale status --json
```

Найденные устройства добавляются в список после подтверждения пользователя. Импортируются только адреса и имена устройств; секреты Tailscale не читаются и не сохраняются.

Наличие устройства в Tailscale не гарантирует доступность SSH. На целевой системе должны работать Dropbear/OpenSSH и правила firewall должны разрешать соединение через `tailscale0`.

### Терминал

Кнопка «Открыть терминал» запускает Windows Terminal с подготовленной SSH-командой:

```text
ssh -p ПОРТ -i ПУТЬ_К_КЛЮЧУ пользователь@адрес
```

Если Windows Terminal отсутствует, используется PowerShell.

## Интерфейс

Главное окно состоит из двух областей:

- слева — общая панель действий для выбранного устройства;
- справа — таблица устройств и их состояний.

Действия:

- открыть терминал;
- удалить сохранённые данные;
- удалить устройство.

## Установка SSH-ключа

Ven4Control генерирует собственную пару Ed25519:

```text
%LOCALAPPDATA%\Ven4Control\ssh\id_ed25519
%LOCALAPPDATA%\Ven4Control\ssh\id_ed25519.pub
```

Приватный ключ получает ограниченный Windows ACL: наследование отключается, чтение разрешается только текущему пользователю.

### OpenWrt

Публичный ключ добавляется в:

```text
/etc/dropbear/authorized_keys
```

Перед изменением создаётся резервная копия:

```text
/root/ven4control-backups/authorized_keys.YYYYMMDD-HHMMSS
```

### Ubuntu/Linux

Публичный ключ добавляется в:

```text
~/.ssh/authorized_keys
```

Резервная копия создаётся в:

```text
~/ven4control-backups/
```

## Хранение данных

Несекретные сведения об устройствах хранятся в SQLite:

```text
%LOCALAPPDATA%\Ven4Control\devices.db
```

В базе находятся:

- название;
- адрес;
- порт;
- пользователь;
- способ входа;
- путь к ключу;
- подтверждённый fingerprint.

Пароли и passphrase не записываются в SQLite. Если включена галка «Сохранять введённые данные», они помещаются в Windows Credential Manager через системный backend `keyring`.

## Безопасность

- сохранение credentials по умолчанию выключено;
- пароль не попадает в Git и SQLite;
- SSH fingerprint показывается перед установкой ключа;
- fingerprint повторно проверяется непосредственно перед изменением `authorized_keys`;
- существующие SSH-ключи не перезаписываются;
- перед изменением `authorized_keys` создаётся backup;
- приватный ключ защищается Windows ACL;
- локальная база, виртуальное окружение и ключи исключены из Git;
- импорт Tailscale не читает ключи, cookies или токены.

## Системные требования

- Windows 10/11;
- Python 3.12 или новее;
- Windows OpenSSH Client;
- Windows Terminal — рекомендуется;
- Tailscale CLI — только для импорта tailnet-устройств.

## Установка из исходников

```powershell
git clone https://github.com/Ven4ru/Ven4Control.git
cd Ven4Control
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .
ven4control
```

Либо:

```powershell
.\.venv\Scripts\pythonw.exe -m ven4control.app
```

## Ограничения версии 1.0

- встроенного терминала пока нет;
- нет файлового менеджера SFTP;
- нет автоматического опроса systemd/procd-сервисов;
- нет групп устройств и массовых действий;
- нет журналирования SSH-команд;
- Tailscale не открывает SSH автоматически;
- Windows-узлы требуют отдельной настройки OpenSSH;
- приложение предназначено для одного локального пользователя.

## Идея Ven4Node

`Ven4Node` рассматривается как отдельный небольшой конфигуратор Windows-компьютеров. Он должен один раз запускаться с UAC и:

- проверять наличие Tailscale;
- устанавливать Windows OpenSSH Server;
- включать `sshd`;
- создавать firewall-правило только для Tailscale;
- добавлять публичный ключ Ven4Control;
- уметь удалить созданный доступ и восстановить настройки.

После настройки постоянный агент не требуется: соединение обеспечивают системные `sshd` и Tailscale.

Эта идея зафиксирована, но отложена. Текущая цель проекта — удобный контроль OpenWrt и Ubuntu.
